# Architecture

A static site: plain HTML, CSS and JavaScript, no build step and no packages. Every Android version is a separate page
that loads only its own files, so a change in one version cannot break another.

## The repository

| Path | What it is |
| --- | --- |
| `index.html`, `app.js`, `styles.css` | The landing page: the version list (`versions/catalog.js`) and the language switch. |
| `i18n.js` | The shared interface texts, keyed by the English text (`AndroidI18n`). |
| `strings.js` | The one reader for every text table (`AndroidStrings`: table, format, plurals); see audit point 10. |
| `state.js` | Loading and saving a version's state in `localStorage` (`AndroidState`); see `docs/saved-state.md`. |
| `versions/<v>/` | One phone: 2.3.6 (Nexus S), 4.0.4 (Galaxy Nexus), 4.3 (Nexus 4), 4.4.4 (Nexus 5), 5.1.1 (Nexus 6). |
| `assets/` | Landing page art and the sounds 2.3.6 shares. |
| `tests/` | Node module tests (`*.test.cjs`) and the headless Chrome flows (`tests/browser/flows.mjs`). |
| `docs/` | The plan, notes and the tools that rebuild the generated files (below). |
| `_aosp/` | The unpacked factory images; not in Git (see `docs/sources.md`). |

## A version folder

`versions/<v>/index.html` is the phone page. It loads the shared `i18n.js`, `strings.js` and `state.js` from the root,
then the version's own stylesheets and scripts. Every reference carries a `?v=` key: raise it whenever that file
changes, or browsers keep the old copy.

- **`simulator.js`** is the core (2,500–4,000 lines). It holds two objects: `data`, the saved state (settings, contacts,
  messages, alarms …, written through `AndroidState`), and `ui`, what is on screen now (`ui.view` = the open app,
  `ui.sub` = its page, `ui.overlay` = a menu or dialog; never saved). `render()` draws `ui.view` with a `switch`,
  `renderOverlay()` draws `ui.overlay`, and `openApp()`, `home()` and the Back handling move between them. All taps go
  through **one click handler**: an element with `data-action="name"` (and optional `data-id`, `data-app`) runs
  `case 'name':` in its `switch (action)`. Forms work the same way through `data-form` and `switch (form.dataset.form)`.
- **App modules** are the other `.js` files: each sets one `window.Name` object (`KKDeskClock`, `LPDownloads`,
  `ICSMessaging` …) with a `render…()` that returns the HTML of its screens and, for larger apps, its own action handler.
  A file name carries the era prefix of the version that owns it (`gb-`, `ics-`, `jb-`, `kk-`, `lp-`) when it is that
  version's own build of an app; files without a prefix are the version's copy of a common module.
- **Stylesheets** follow the modules (`kk-deskclock.css`, `lp-downloads.css` …); `style.css` holds the frame, the
  launcher basics and shared widgets. Every size on the screen is dp: `calc(N * var(--dp))`, with `--dp` set at the top
  of `style.css` to the frame's scale (1 dp in px of the drawn display) and, at phone width, to `100vw / <dp width>`, so
  the display fills a phone proportionally. The page around the phone (header, intro, frame, keys) stays in px. Scripts
  that need a length in px read one dp from the screen (`dp(n)`, `DP()`) instead of keeping a number.
- **Generated files** start with a comment naming their generator (`Generated by docs/tools/…`). Do not edit them by
  hand: change the template or the generator and run it again, or the next regeneration undoes the change. Generators
  that write a stylesheet pass it through `docs/tools/dp_css.py`, so their px come out in dp like the rest
  (`docs/tools/px-to-dp.mjs` did the same once for the hand-written stylesheets).
- **`assets/`** are the image's own pictures, sounds and fonts. A name prefix tells the app they come from; the row in
  `docs/reports/assets/<v>.tsv` gives the exact file in the factory image.

Three rules hold the folders together: every version owns its files (two versions do not ship the same file byte for
byte, apart from the few logic-only files `tests/version-files.test.cjs` lists); what a screen shows comes from that version's own factory image, cited in the
file's header comment; and the shared root files contain no version's look.

## Fixing or changing an app

1. Open the screen in the browser and inspect the element: its `data-action` is the name to look for.
2. Search the version folder for `case 'that-name':`. It is in `simulator.js` or in the app's module.
3. The screen's HTML is in the module's `render…()` (or in `render()` of `simulator.js` under `case 'app-id':`).
4. If the file is generated, change `docs/templates/` or `docs/tools/` instead and rerun the generator.
5. Take the change from the factory image (layout XML, strings, drawables, code in the odex); `docs/sources.md` says how.
6. Raise the `?v=` key of every changed file in that `index.html`, then run the checks below.

## docs/

| Folder | Contents |
| --- | --- |
| `docs/` | The audit plan, this file, `sources.md` (images and regeneration), `saved-state.md`, the feature lists and the visual audits. |
| `docs/tools/` | Generators (`*.py`, `*.mjs`) that rebuild files from the factory images, and the checks. |
| `docs/templates/` | The `*.template.js` / `.css` files the generators fill in. |
| `docs/data/` | Fixed inputs of the generators (`image-strings-<v>.res`, `asset-sources.tsv` …). |
| `docs/reports/` | What the checks and generators write (`*-check.md`, `asset-inventory.md`, `assets/<v>.tsv` …). |

## Checks

| Command | What it checks |
| --- | --- |
| `npm test` | All module tests (also run on every push by `.github/workflows/tests.yml`). |
| `npm run test:browser` | Boot, unlock, Settings, Back, power, languages and saved-state checks, including Nougat's fresh demo, two old-save upgrades and five-language app/preferences sweep (needs a local server, `php -S localhost:8090 -t .`). |
| `npm run regenerate:texts` | Reruns every text generator; fails if a generated file would change. |
| `npm run regenerate:assets` | Rebuilds the asset inventory from the images; fails on any difference. |
| `npm run check:unused-assets` | Asset files nothing uses. |
| `npm run check:unused-css` | CSS rules and `@keyframes` no code can reach (`--write` removes them). |
| `npm run check:unreachable` | `case` branches whose name nothing produces (dead actions, forms and views). |
| `npm run check:texts`, `check:assets`, `check:fonts` | Missing translations, failed asset requests and font sources, opened in headless Chrome; reports in `docs/reports/`. |
| `node docs/tools/layout-dump.mjs <v> <out.json>` | The box of every element of every app and a few seeded taps in it (fixed clock, seeded randomness). Dump before and after a CSS change and compare with `--compare a.json b.json`; a dump with `--phone WxH` (a display of the desktop display's shape) compared at `--scale k` shows what does not scale with the screen. |

The live site (android.levente.net) is a plain `git pull` of `main` on the server; nothing is built there.
